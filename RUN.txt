WoW 12.0.7 Firestorm — 当前分支的准确状态
================================================

重要：仓库原有 wowmod.exe / wowmod_hook.dll 可能是旧预编译文件，不能假设它包含本分支新增的
Arctium 预检命令。请从当前源码重新构建后再运行。当前 Arctium 代码只生成映射预检表，
没有安装客户端 hook，也没有确认游戏内纹理替换。

当前分支已经包含：
  - 89 个 BloodElf Female .blp 纹理（12,208,284 字节）；
  - 89/89 条来自 wowdev/wow-listfile 分类 CSV 的路径 -> FileDataID 映射；
  - 独立于旧 VFS 的 `arctium-plan` 命令。

第 1 步：构建当前源码
------------------------------------------
  cmake -S . -B build
  cmake --build build --config Release

PowerShell 下生成的 CLI 一般在：
  .\build\Release\wowmod.exe

第 2 步：运行 Arctium 映射预检（不启动游戏）
------------------------------------------
从仓库根目录执行：

  .\build\Release\wowmod.exe arctium-plan --config .\examples\12.0.7\wowmod.firestorm.json

导出机器可读结果：

  .\build\Release\wowmod.exe arctium-plan --config .\examples\12.0.7\wowmod.firestorm.json --json > arctium-plan.json

预期：映射文件 89 条；扫描文件 90 个（额外的 README.md 没有 ID，会忽略）；映射 89 个，重复 ID 0，
无效 ID 0。JSON 的 `status` 是 `preflight-only`、`hookInstalled` 是 `false`，表示只做输入预检。

第 3 步：当前还不能宣称游戏内替换
------------------------------------------
`wowmod launch` 仍走仓库旧的注入/VFS 实验流程，不是完成的 Firestorm 12.0.7 Arctium runtime。
不要把客户端窗口启动、线程退出码为 0、DLL 本地加载成功或静态映射预检通过当成资源替换成功。
目前也没有证据确认客户端存在反注入/白名单保护。

要继续实现并验证运行时 FileDataID hook，需要 Windows 采集以下文件：
  runtime-dumps\wow_loader.dll.img
  runtime-dumps\wow_loader.dll.candidates.json
  runtime-dumps\runtime-report.json
  wowmod.log（保留完整注入报告）

配置应保持 `runtimeScan: true`、`runtimeDelayMs: 15000`、`runtimeAutoInstall: false`。
若 DLL 没有进入目标进程，runtime dump 也不会产生；请保留完整日志。替代方案是用 x64dbg 提供已解密模块名、
目标函数 RVA、入口前后 24–32 字节、ID 所在寄存器/栈槽及宽度、命中/未命中时的返回值语义。

不需要重发替换包、客户端路径或安装目录截图；公开 listfile 的 89 条映射已经找齐，无需再爬全量游戏数据。
如果需要证明 Firestorm 12.0.7 的本地 CASC 归档中包含这些 ID，仍需从该客户端本地数据单独验证。

当前开发环境是 Linux，没有 Windows 交叉编译器或 Wine；Linux 单元测试通过不代表 Windows 构建或游戏内测试通过。
详细状态见 docs\ARCTIUM-STYLE.md 和 examples\12.0.7\README.md。
