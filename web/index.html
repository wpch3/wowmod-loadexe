WoWMod Loader v1.0.0

by wpch3 · 通用版本 WoW 模型替换 / 模组加载器

启动客户端时应用当前启用的模组配置，把模型、材质、插件与配置映射进游戏；不修改磁盘上的任何游戏文件。

与按版本写死偏移的加载器不同，这里没有任何内置版本号、偏移或特征表。

● 任意版本已支持build —
01 · 无版本白名单版本只从 .build.info / PE 版本资源读取，用于展示与筛选，从不用于拒绝启动。
02 · 稳定 API 覆盖IAT 层拦截 CreateFileW / NtCreateFile 等 Win32 API，所有版本一致。
03 · 数据驱动适配CASC 的 FileDataID 注入点来自外部 patterns.json，加一条数据即适配新 build。

WoW 12.0.7 专用流程

仓库里的 examples/12.0.7/ 是给 12.0.7 准备的起始包（配置、listfile 位置、多特征文件）。

  1. 路径型覆盖立刻生效：detect 显示「已支持」、plan 显示 VFS 覆盖表，无需任何特征。
  2. 让 CASC 按 ID 读取的模型也生效：wowmod adapt --exe Wow.exe --pattern "邻近 12.x 的特征" --out hooks/patterns.adapted.json，工具会自动放宽成你这个 exe 上唯一匹配的特征。
  3. 验证：wowmod scan 看唯一匹配，wowmod plan 的 hook 模式变成 fileid。

跨大版本的起点特征需要放宽较多字节，工具会给出 ⚠ 提示；最可靠的起点是同家族（12.1.x）的特征。详见 docs/ADAPTING.md。

适配新版本的三步

  1. 放文件：把模型/材质按游戏内路径放进模组目录（或写 wowmod.manifest.json 按 FileDataID 指定）。
  2. 给 listfile：把该版本的 fileId;filePath 表放进 mappings/，路径覆盖会自动得到 ID。
  3. 可选加特征：只有需要 CASC 的「按 ID 读文件」注入时，才为这个 exe 加一条特征；加完用 wowmod scan 验证唯一性。
